# Исправления по аудиту MoneyGraph

23 сентября 2026. Базовая версия аудита: `c9f6886d0eafaef6fac3a728bf5fe96db23f3473`.

## Закрытые дефекты

| Дефект | Исправление и проверка |
|---|---|
| LLM выдумывает пороги, интервалы и ссылки | Модель выбирает инструменты одним запросом; ответ формируется кодом из результатов. Свободный текст модели игнорируется. Регрессия подставляет выдуманные числа, обвинение и чужой gid и проверяет их отсутствие в ответе. |
| Модель добавляет неподтверждённые даты или узлы | Аргументы проверяются относительно вопроса, выбранной карточки и ограниченной истории. Даты периода принимаются только из сообщений пользователя. Неподтверждённые вызовы отклоняются. |
| Нет назначения кластеров | Добавлены осторожные гипотезы функции сообщества с составом ролей, внутренним и внешними потоками, количеством seed и граничных узлов. |
| Новое окружение обрезается на графе | Масштаб пересчитывается при выборе узла. «Вместить» сохраняет текущий подграф; отдельная кнопка показывает всю сеть и сбрасывает фильтры. |
| Enter во время ответа стирает следующий вопрос | Проверка занятости выполняется до очистки поля. Регрессия проверяет сохранение черновика. |
| Повторные загрузки создают вложенные каталоги | Корень результатов фиксирован; версии располагаются рядом по хешу набора. Повтор одного ZIP использует тот же каталог. |
| Float gid теряет точность; неверная глубина принимается | Идентификаторы принимаются только как целые или строгие десятичные строки. Проверяются достижимость, минимальная глубина от всех seed и глубина обнаружения ребра. |
| Смена набора сбрасывает общий бюджет LLM | Все версии ассистента используют один потокобезопасный счётчик. Проверка: 12 конкурентных запросов при лимите 3. |
| Повреждённый ответ API приводит к HTTP 500 | Проверка структуры ответа и локальный fallback, включая `message=null`. |
| Загрузкой ZIP нельзя пользоваться с клавиатуры | Сохранён доступный нативный file input и добавлена видимая индикация фокуса. |
| Старый ответ появляется после смены набора | Клиентские поколения запросов и хеш набора предотвращают смешение результатов; устаревший запрос получает HTTP 409. |

## Усиление обязательных функций

- `role_rules` — единый источник условий для назначения роли, карточки и ассистента. Показаны фактические значения, вторичные признаки и отсутствие временной поддержки.
- Приоритет проверяется в десяти сценариях изменения весов на ±20%. На исходном наборе сохраняется минимум 18 из 20 лидеров, в среднем 19,4. Это проверка чувствительности, не точности классификации.
- Добавлены инструменты кластера и периода, история до 6 сообщений/2400 символов. Большие результаты инструментов не возвращаются в контекст модели.
- Ограничения количества строк, обязательных колонок и заявленного распакованного объёма Parquet проверяются до декодирования таблиц; лишние колонки не читаются.
- Три обязательных CSV приложены в `submission/`, их контрольные суммы — в `manifest.json`. Скрипт `scripts/package_submission.py` воспроизводит пакет.
- GitHub Actions настроен проверять Python и JavaScript на Windows и Linux и собирать демо-CSV. Первый запуск заблокирован GitHub до начала шагов из-за billing issue аккаунта (см. `VALIDATION.md`). Шесть тестов исходного набора требуют локальных файлов организаторов и без них пропускаются.

## Что остаётся ограничением

Это локальный исследовательский прототип. Роли и назначение кластеров — эвристические гипотезы, а не установленные преступные связи. Эталонной разметки нет, поэтому качество распознавания реальных ролей не измерено. Отсутствие исходящих на четвёртом колене не подтверждает накопление денег.

Проверка весов не заменяет исследование чувствительности порогов, seed и параметров Louvain. Пути топологические; поиск временных циклов, повторяющихся маршрутов и моделирование удаления узлов остаются направлениями развития. LLM может выбрать не самый подходящий из допустимых инструментов; пользователь видит его аргументы и проверяемый результат.

Сервер предназначен для одного локального пользователя; ограничение Parquet по метаданным не является изоляцией памяти отдельного процесса. Производственная многопользовательская эксплуатация и масштаб в миллион узлов требуют другой архитектуры.

Фактические результаты проверок и живой интеграции — в `VALIDATION.md`.
